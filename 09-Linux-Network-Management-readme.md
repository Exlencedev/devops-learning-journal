# 🌐 Linux Ağ & Port Yönetimi

Bu belge, DNS sorgulamayı (`dig`), dinleme portlarını (`ss`), ve TLS sertifika doğrulamayı (`openssl`) kapsıyor. Bu fazda, Rocky Linux minimal kurulumun beklenenden daha "çıplak" olduğu iki kez ortaya çıktı — hem `dig` hem `openssl` ayrıca kurulması gerekti.

---

## 1. DNS Sorgulama (`dig`)

### 🐛 Hata & Çözüm: Araç Eksikliği

```bash
dig google.com
```
**Sonuç:** `bash: dig: komut yok`

`dig`, Rocky Linux minimal kurulumda varsayılan olarak gelmiyor — `bind-utils` paketinin bir parçası:

```bash
sudo dnf install bind-utils -y
```

### Sorgu Karşılaştırması

```bash
dig google.com
dig @8.8.8.8 google.com
```

**Sonuç:** İki sorgu da aynı sunucuya (`SERVER: 8.8.8.8#53(8.8.8.8)`) gitti, aynı cevabı (`216.239.38.120`) döndürdü — beklenen "yerel vs public DNS farkı" gözlenemedi.

### 🔍 Sebep Analizi

```bash
cat /etc/resolv.conf
```
**Çıktı:**
```
# Generated by NetworkManager
nameserver 8.8.8.8
nameserver 9.9.9.9
nameserver fd17:625c:f037:2::3
```

Sistemin varsayılan resolver'ı zaten **8.8.8.8** (Google) olarak yapılandırılmış (VirtualBox NAT ağı veya kurulum varsayılanı). Bu yüzden iki sorgu da aynı sonuca gitti.

### 🧠 Öğrenilen Ders

DNS sorun giderirken varsayımda bulunmak yerine `/etc/resolv.conf`'a bakıp **gerçek yapılandırmayı** doğrulamak gerekir — teorik beklenti (yerel ≠ public DNS) ile gerçek ortam (ikisi aynı sunucuya yönlendirilmiş) farklı çıkabilir.

## 2. Dinleme Portlarını Kontrol Etme (`ss`)

```bash
sudo ss -lntp | grep :80
```

**Çıktı:**
```
LISTEN  0  511  0.0.0.0:80  0.0.0.0:*  users:(("nginx",pid=2102,fd=6),("nginx",pid=2101,fd=6),("nginx",pid=2098,fd=6))
LISTEN  0  511     [::]:80     [::]:*  users:(("nginx",pid=2102,fd=7),("nginx",pid=2101,fd=7),("nginx",pid=2098,fd=7))
```

### 🔍 Gözlem

Nginx, hem **IPv4** (`0.0.0.0:80`) hem **IPv6** (`[::]:80`) üzerinde 80 portunu dinliyor. Ayrıca **3 farklı PID** (2098, 2101, 2102) aynı porta bağlı görünüyor — bu, nginx'in **master process + worker process'ler** mimarisinden kaynaklanıyor (06. fazda `top`'ta gözlemlenen worker process'lerle aynı yapı).

### `-l` vs `-a`

| Flag | Gösterdiği |
|------|------------|
| **`-l`** | Yalnızca **dinleyen** soketler |
| **`-a`** | Dinleyenler **+** kurulu bağlantılar |

"Bu portta ne dinliyor?" sorusu için `-l` doğrudan ve yeterli cevaptır.

## 3. TLS Sertifika Kontrolü (`openssl`)

### 🐛 Hata & Çözüm: Yine Araç Eksikliği

```bash
openssl s_client -connect example.com:443 -showcerts
```
**Sonuç:** `bash: openssl: komut yok`

```bash
sudo dnf install openssl -y
```

### Sonuç

```bash
openssl s_client -connect example.com:443 -showcerts
```

**Önemli satırlar:**
```
Verify return code: 0 (ok)
Protocol    : TLSv1.3
Cipher      : TLS_AES_256_GCM_SHA384
```

- **`Verify return code: 0 (ok)`** → `example.com`'un sertifikası geçerli ve güvenilir — sertifika zinciri (root CA'dan siteye kadar) sağlam.
- **`Protocol: TLSv1.3`** → Güncel, güvenli protokol versiyonu.
- **`Cipher: TLS_AES_256_GCM_SHA384`** → Güçlü, modern şifreleme.

### Sertifika Güven Zinciri Kavramı

- **`depth=N` (en yüksek, Root CA):** İşletim sistemi tarafından varsayılan olarak güvenilir.
- **`depth=1` (Yayımlayan CA):** Bu domain için sertifikayı yayımlar.
- **`depth=0` (Son varlık):** Asıl site (`example.com`).

## 🧠 Öğrenilen Genel Ders: Minimal Kurulumun Gerçek Anlamı

Bu fazda iki kez ("dig" ve "openssl" için) araç eksikliğiyle karşılaşıldı. Rocky Linux **minimal** kurulumu gerçekten minimal — ağ/güvenlik teşhis araçlarının çoğu varsayılan olarak gelmiyor, ihtiyaç oldukça (`dnf install <paket>`) ayrıca kurulmalı. Doğru paket adını bulup (`dig` → `bind-utils`) hızlıca kurabilmek, gerçek DevOps işinin sıradan bir parçası.

## 📊 Komut Referansı

| Araç | Protokol Katmanı | Örnek | Amacı |
|------|-------------------|-------|-------|
| **`dig`** | UDP / 53 | `dig @8.8.8.8 google.com` | DNS kayıtlarını sorgular, belirli bir resolver hedefleyebilir |
| **`cat /etc/resolv.conf`** | — | `cat /etc/resolv.conf` | Sistemin gerçekte kullandığı DNS sunucularını gösterir |
| **`ss`** | TCP/UDP | `sudo ss -lntp` | `-l` dinleyen soketleri, `-a` dinleyenler+bağlantıları gösterir |
| **`openssl s_client`** | TCP / 443 | `openssl s_client -connect site:443` | TLS sertifikasının geçerliliğini ve güven zincirini inceler |
